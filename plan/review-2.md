## 2. 新規発見の問題

### N-1 [MED] master Blowfish キー所在調査が Phase A の go/no-go に含まれていない

- B-6 が「A-3 で銀行連携/メール取込が『使う』と判明した場合のみ」と条件付きになっているが、もし「使う」かつ「キー入手不能」が同時成立すると **renewal 切替不可 or 大規模なユーザー再入力作業** が発生する。
- これは Phase A 段階で潰すべきリスクで、**A-3 ヒアリング (Q-1a/b/c) と並走して「マスター Blowfish キーの所在確認」タスク** を A-3.1 として追加するのが望ましい。

### N-2 [LOW] RC-8「期首残高一致確認」の合格基準が曖昧

- 「master の各期 BS 開始残高と renewal の BS 開始残高が一致」とあるが、**どの粒度で一致を見るか**（科目別 / 補助科目別 / 部門別）が未定義。
- 「100% 一致」を機械チェックする道具 (Golden test の延長) もまだ無い。RC-8 は B-2 Golden 機械化と相互依存しているが、計画書上は順序関係が不明確（RC は Phase A 前のリアリティチェックで、B-2 は Phase B 内）。
- 提案: RC-8 は「目視 + 主要科目 (現金/預金/売掛/買掛/資本) のサンプリング一致」レベルに留め、B-2 で機械化された後に「全科目 100% 一致」へ昇格、と明示。

### N-3 [LOW] §0 の「三大ギャップ」と §2.2 の「要検証」と §3 RC リスト の対応関係が読みづらい

- G-1 (FEATURE_* 未実装) → A-5 / Q-6
- G-2 (期首残高ゼロ) → RC-8 / A-2 / R-11
- G-3 (性能 100 倍ギャップ) → RC-7 / B-5 / D-1 / Q-4
- これらの対応表を §0 直下に小さくまとめると、計画書を読む人が「ギャップ → 検証 → 対応 Phase」を追いやすい。**読みやすさだけの問題で content には影響なし**。

### N-4 [LOW] Phase F (機能削減) の発火条件が緩い

- F-1「A-3 で『不要』と確定した renewal モジュール (Budget / BEP 等) を retire」とあるが、A-3 は Q-2 の回答待ちであり、「retire の判断は誰がいつ行うか」「retire 前にコード/テスト/ADR をどう archive するか」が未定義。
- 提案: F-1 を「(i) Q-2 回答後に対象モジュール一覧確定 → (ii) ADR 作成 → (iii) Phase E 完了後に削除」と分割。

### N-5 [LOW] §9 のドキュメント同期タスクに ADR-002 / docs/PLAN.md の「10 万仕訳」記述更新が抜け

- review-1 H-2 で性能目標と本データの 100 倍ギャップを指摘し、計画書 v2 で立場は明確化されたが、**`docs/PLAN.md:163` / `docs/adr/ADR-007:456` / `docs/adr/ADR-002:559,607,668` の数値そのもの** を更新するタスクが §9 の列挙に含まれていない。
- A-4 のギャップ表に紛れ込ませる前提なら問題ないが、明示しておく方が漏れにくい。

## 3. 最終判定

**判定: needs-fix（軽度）**

### 理由

- review-1 の指摘 15 件中 12 件が完全反映、3 件が部分反映、未対応は 0 件。**主要な事実誤認・致命的な技術ギャップ (Phase C 誤認 / 期首残高破綻 / 性能ギャップ / Strangler Fig 乖離) はすべて対処方針が明文化された**。
- 残る不十分点 (H-5, M-4 ロールバック手順, L-3 鍵管理) と新規問題 (N-1〜N-5) は **いずれも Phase A 着手後に並走解決可能** な軽度のもので、計画全体を blocked にする要素は無い。
- 「continue（条件付き継続）」という結論および Phase A〜F の枠組みは健全。あとは Phase A の実施と §7 ヒアリング回答で詳細スコープを確定するフェーズに移れる。

### needs-fix で残す軽度修正項目

1. **H-5 補強**: A-3.1 として「master Blowfish キー所在確認」を追加し、A-3 と並走させる（B-6 の前提潰し）
2. **N-1**: 上記 A-3.1 と同じ
3. **M-4 補強**: A-2 または A-6 に「import 失敗時のロールバック手順 (`legacy_id_mapping` 等の truncate 手順)」を明記
4. **N-2**: RC-8 の合格基準を「主要科目サンプリング (Phase A 段階) → 全科目自動 (Phase B-2 機械化後)」と二段階化
5. **N-5**: §9 に「ADR-002 / docs/PLAN.md / ADR-007 の 10 万仕訳記述を実データ規模に更新」を追加

### 次のアクション

1. **上記 needs-fix 5 項目を計画書 v3 に反映**（30 分〜1 時間程度の作業）
2. **§7 のユーザー確認事項 Q-1〜Q-6 をユーザーに提示** → 回答取得
